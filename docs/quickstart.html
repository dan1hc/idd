IDD Quick Start

Give Copilot Chat a durable working memory for your repository.

1. Install

curl -fsSL https://raw.githubusercontent.com/dan1hc/idd/main/install.sh | bash

This scaffolds the IDD file tree, downloads .github/copilot-instructions.md and the feature template, creates the top-level Markdown artifacts if they are missing, and mirrors the same operating contract to .cursorrules and CLAUDE.md.

2. Open Copilot Chat

After install, work through Copilot Chat. For example:

1. Discover this repository and populate the IDD context files.
2. Create a feature spec for audit logging using the current IDD artifacts.
3. Implement the active feature and update its glossary before finishing.

The chat operating contract lives in .github/copilot-instructions.md. That file tells the agent which artifacts to read, which files to update, and how to handle discovery, planning, implementation, glossary maintenance, and evidence-backed consistency review.

3. Markdown artifacts

IDD now uses Markdown-first context files instead of JSON runtime artifacts.

  • .github/idd/architecture.md — system shape, runtime topology, integrations, and open questions
  • .github/idd/conventions.md — code style, boundaries, library patterns, and component placement
  • .github/idd/inventory.md — projects, modules, entrypoints, routes, jobs, and evidence
  • .github/idd/learned.md — explicit user-approved rules that override discovered conventions
  • .github/idd/features/*.md — bounded feature specs with acceptance criteria and glossary anchors

4. Feature specs

Feature files record the intended work, constraints, dependencies, and a glossary of stable file::symbol anchors. The glossary is how future agents find what was implemented.

File tree

.github/
├── copilot-instructions.md # primary operating contract for Copilot Chat
└── idd/
  ├── architecture.md     # system shape and runtime topology
  ├── conventions.md      # coding patterns and boundaries
  ├── inventory.md        # repository surfaces and evidence
  ├── learned.md          # explicit user-approved rules
  └── features/
    ├── _template.md    # feature spec template
    └── *.md            # project features
