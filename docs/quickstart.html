IDD Quick Start

Intent-Driven Development — make AI follow your conventions

Install

curl -fsSL https://raw.githubusercontent.com/dan1hc/idd/main/install.sh | bash

This downloads the IDD CLI, detects your project's conventions, and copies instructions to where your AI tools look.

Three Commands

1 idd init

Detect conventions and copy instructions.md to tool locations (.cursorrules, CLAUDE.md, .github/copilot-instructions.md).

.github/idd/idd init

2 idd detect

Re-detect conventions after changing formatters, linters, or project structure.

.github/idd/idd detect

3 idd learn

Add a project rule that persists across AI sessions.

.github/idd/idd learn "Always use BaseClient, never raw httpx"

The Loop

  1. Create a feature spec — copy _template.md to features/my-feature.md
  2. Open your AI tool — Cursor, Claude Code, or GitHub Copilot
  3. AI reads instructions — it loads conventions, learned rules, and the feature spec
  4. AI writes matching code — follows your formatting, naming, patterns
  5. AI updates the glossary — the feature file tracks what was built and where

No compilation. No agent orchestration. Files in the places AI already looks.

File Tree

.github/idd/
├── idd                              # CLI (init, detect, learn)
├── instructions.md                  # AI reads this
├── conventions.json                 # Auto-detected conventions
├── learned.json                     # Human-confirmed rules
├── features/
│   ├── _template.md                 # Feature spec template
│   └── *.md                         # Your feature specs
└── schemas/
    ├── conventions.schema.json      # conventions.json schema
    └── learned.schema.json          # learned.json schema

What Gets Detected

  • ✓ Language & framework
  • ✓ Formatting (indent, quotes, line length)
  • ✓ Naming conventions (functions, classes, files)
  • ✓ Testing (framework, location, naming)
  • ✓ Logging (library, style)
  • ✓ Centralized components (models, enums, services)
